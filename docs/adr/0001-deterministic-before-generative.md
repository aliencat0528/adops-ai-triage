# ADR-0001 · 已知故障先走規則引擎，LLM 只處理模糊案例

**狀態**：採納 · 2026-08-23

## 背景
分診與診斷都可以直接丟給 LLM，實作最快。

## 決策
已知故障模式先經過版本控管的規則引擎；只有規則接不住的案例才進 LLM。

## 理由
- **可稽核**：規則命中的判斷可以逐條解釋，LLM 不行
- **成本**：規則命中不花 token；依模擬資料，可規則化的案例佔多數
- **穩定**：規則不會因模型版本更新而改變行為
- **可回歸**：規則變更可寫單元測試，prompt 變更只能跑黃金集抽樣

## 後果
- 需維護規則庫，且規則與 LLM 的界線要定期檢視
- L6 學習層的職責之一是「把 LLM 反覆處理對的案例，沉澱成規則」
